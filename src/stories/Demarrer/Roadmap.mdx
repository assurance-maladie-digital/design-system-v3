## Cycle de versions

Synapse suit la gestion sémantique de version (`MAJEURE.MINEURE.CORRECTIF`). Le type de version vous indique l'effort à prévoir pour mettre à jour votre projet : aucune adaptation pour un correctif, des adaptations légères pour une mineure, une migration planifiée pour une majeure.

<div className="roadmap-cycles">

| Type | Exemple | Contenu | Rythme | Impact pour votre projet |
| --- | --- | --- | --- | --- |
| **Correctif** | `1.1.5` → `1.1.6` | Corrections d'anomalies, améliorations d'accessibilité, documentation, petites évolutions rétrocompatibles. | Toutes les 3 semaines environ. | <span className="roadmap-impact roadmap-impact--patch">Aucune adaptation</span><br/>Montée de version conseillée. |
| **Mineure** | `1.0.x` → `1.1.0` | Nouveaux composants ou fonctionnalités, changements de comportement par défaut, évolution des prérequis (Node, Starter Kit). | Quelques fois par an, selon les chantiers de la roadmap. | <span className="roadmap-impact roadmap-impact--minor">Adaptations légères</span><br/>Signalées par une alerte sur la page [Releases](/docs/démarrer-releases--docs). |
| **Majeure** | `1.x` → `2.0.0` | Changements non rétrocompatibles : refonte d'API de composants, montée de version de socle (Vue, Vuetify), évolution structurante des tokens. | Rare, préparée en amont. | <span className="roadmap-impact roadmap-impact--major">Migration planifiée</span><br/>Accompagnée d'un guide de migration. |

</div>
