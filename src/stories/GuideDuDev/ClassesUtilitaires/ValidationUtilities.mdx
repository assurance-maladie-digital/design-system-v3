## propValidator

Cette fonction facilite la validation des props dans les composants Vue.

### Importation

<Source dark code={`import { propValidator } from '@cnamts/synapse'
`}/>

### Utilisation

<Source dark code={`export default {
  props: {
    // Valider une prop avec des valeurs spécifiques
    size: {
      type: String,
      // propValidator prend la valeur en 3e argument : on la passe via le validator
      validator: (value) => propValidator('size', ['small', 'medium', 'large'], value)
    },
    
    // Valider une prop avec des valeurs numériques (comparées sous forme de chaîne)
    priority: {
      type: Number,
      validator: (value) => propValidator('priority', ['1', '2', '3', '4', '5'], String(value))
    }
  }
}
`}/>

### Exemple pratique

<Source dark code={`<template>
  <div :class="\`button-\${size}\`">
    <slot />
  </div>
</template>

<script>
import { propValidator } from '@cnamts/synapse'

export default {
  name: 'CustomButton',
  props: {
    size: {
      type: String,
      default: 'medium',
      validator: (value) => propValidator('size', ['small', 'medium', 'large'], value)
    },
    variant: {
      type: String,
      default: 'primary',
      validator: (value) => propValidator('variant', ['primary', 'secondary', 'outline', 'text'], value)
    }
  }
}
</script>
`}/>

## ruleMessage

Cette fonction récupère le message associé à une clé dans une table de messages (`ErrorMessages`) : la valeur peut être une chaîne ou une fonction appelée avec les arguments fournis. Elle sert à construire des règles de validation personnalisées compatibles avec les règles du Design System (`isRequired`, `isMinLength`…).

### Importation

<Source dark code={`import { ruleMessage } from '@cnamts/synapse'
`}/>

### Utilisation

<Source dark code={`const messages = {
  default: 'La valeur est invalide',
  minLength: (min) => 'Minimum ' + min + ' caractères'
}

// Message simple
ruleMessage(messages, 'default') // 'La valeur est invalide'

// Message fonction, avec arguments
ruleMessage(messages, 'minLength', [8]) // 'Minimum 8 caractères'
`}/>

### Exemple pratique : une règle personnalisée

<Source dark code={`<script>
import { ruleMessage } from '@cnamts/synapse'

// Fabrique de règle compatible avec :rules (Vuetify) et custom-rules (DS)
const isSiretFn = (errorMessages = { default: 'Le SIRET doit contenir 14 chiffres' }) =>
  (value) => {
    if (!value) return true // champ vide : laisser une règle required gérer
    return /^\\d{14}$/.test(value) || ruleMessage(errorMessages, 'default')
  }

// Usage
const siretRules = [isSiretFn()]
</script>
`}/>

> **Note** : pour les cas courants, préférez les règles prêtes à l'emploi du catalogue ([Règles de validation](/?path=/docs/guide-du-dev-utilitaires-r%C3%A8gles-de-validation--docs)) ou les `custom-rules` des composants du DS.

## Validation de dates

> **⚠️ Formats attendus** : `isDateAfter`, `isDateBefore` et `isDateValidUtil` acceptent le format `DD/MM/YYYY`. `isDateInRange` et `isWeekend` attendent le format ISO `YYYY-MM-DD` (via `dayjs`).

### isDateAfter

Vérifie si une date est postérieure à une autre date.

#### Importation

<Source dark code={`import { isDateAfter } from '@cnamts/synapse'
`}/>

Signature : `isDateAfter(dateReference, valeur)` — retourne `true` si `valeur` est strictement postérieure à `dateReference`.

#### Utilisation

<Source dark code={`// Chaînes de dates au format DD/MM/YYYY
isDateAfter('10/02/2023', '15/02/2023') // true : 15/02 est après 10/02
isDateAfter('15/02/2023', '10/02/2023') // false
`}/>

### isDateBefore

Vérifie si une date est antérieure à une autre date.

#### Importation

<Source dark code={`import { isDateBefore } from '@cnamts/synapse'
`}/>

Signature : `isDateBefore(dateReference, valeur)` — retourne `true` si `valeur` est strictement antérieure à `dateReference`.

#### Utilisation

<Source dark code={`// Chaînes de dates au format DD/MM/YYYY
isDateBefore('15/02/2023', '10/02/2023') // true : 10/02 est avant 15/02
isDateBefore('10/02/2023', '15/02/2023') // false
`}/>

### isDateInRange

Vérifie si une date est comprise dans une plage de dates.

#### Importation

<Source dark code={`import { isDateInRange } from '@cnamts/synapse'
`}/>

Signature : `isDateInRange(date, debut, fin, interval?)`. Le paramètre `interval` contrôle l'inclusion des bornes : `'[)'` par défaut (début inclus, fin exclue), aussi `'[]'`, `'()'` ou `'(]'`.

#### Utilisation

<Source dark code={`// Chaînes de dates au format ISO YYYY-MM-DD
isDateInRange('2023-02-15', '2023-02-10', '2023-02-20') // true
isDateInRange('2023-02-05', '2023-02-10', '2023-02-20') // false

// Borne finale incluse
isDateInRange('2023-02-20', '2023-02-10', '2023-02-20', '[]') // true
`}/>

### isDateValidUtil

Vérifie si une chaîne de date est valide (format `DD/MM/YYYY`). Retourne `true` si la date est valide, sinon un **code d'erreur** (`'wrongFormat'`, `'monthNotMatch'`, `'notALeapYear'`) : utilisez `=== true` pour tester la validité.

> **Ne pas confondre** : `isDateValidUtil` est la fonction bas niveau (`true` ou code d'erreur). La **règle** `isDateValid` (instance) est prête à l'emploi dans `:rules`/`custom-rules` et retourne `true` ou un message traduit.

#### Importation

<Source dark code={`import { isDateValidUtil } from '@cnamts/synapse'
`}/>

#### Utilisation

<Source dark code={`// Date valide
isDateValidUtil('15/02/2023') // true

// Dates invalides : un code d'erreur est retourné (pas false)
isDateValidUtil('31/02/2023') // 'notALeapYear' (2023 n'est pas bissextile)
isDateValidUtil('date invalide') // 'wrongFormat'
isDateValidUtil('2023-02-15') // 'wrongFormat' — le format attendu est DD/MM/YYYY
`}/>

### isWeekend

Vérifie si une date correspond à un jour de week-end (samedi ou dimanche).

#### Importation

<Source dark code={`import { isWeekend } from '@cnamts/synapse'
`}/>

#### Utilisation

<Source dark code={`// Chaînes de dates au format ISO YYYY-MM-DD
isWeekend('2023-02-18') // true (samedi)
isWeekend('2023-02-19') // true (dimanche)
isWeekend('2023-02-20') // false (lundi)
`}/>

## Validation d'email

### isEmailValid

Vérifie si une chaîne est un email valide.

#### Importation

<Source dark code={`import { isEmailValid } from '@cnamts/synapse'
`}/>

#### Utilisation

<Source dark code={`// Emails valides

## Exemple pratique complet

Voici un exemple de formulaire utilisant plusieurs utilitaires de validation :

<Source dark code={`<template>
  <v-form ref="form" v-model="isFormValid">
    <v-text-field
      v-model="formData.email"
      label="Email"
      :rules="emailRules"
    />
    
    <v-text-field
      v-model="formData.startDate"
      label="Date de début"
      placeholder="JJ/MM/AAAA"
      :rules="startDateRules"
    />
    
    <v-text-field
      v-model="formData.endDate"
      label="Date de fin"
      placeholder="JJ/MM/AAAA"
      :rules="endDateRules"
    />
    
    <v-btn
      color="primary"
      :disabled="!isFormValid"
      @click="submitForm"
    >
      Valider
    </v-btn>
  </v-form>
</template>

<script>
import { ref, reactive, computed } from 'vue'
import {
  isEmailValid,
  isDateValidUtil,
  isDateAfter,
  isWeekend,
  parseDate
} from '@cnamts/synapse'

export default {
  setup() {
    const form = ref(null)
    const isFormValid = ref(false)
    
    const formData = reactive({
      email: '',
      startDate: '',
      endDate: ''
    })
    
    // isWeekend attend le format ISO : conversion depuis DD/MM/YYYY via parseDate
    const isWeekendDate = (v) => isWeekend(parseDate(v).format('YYYY-MM-DD'))
    
    // Règles de validation pour l'email
    const emailRules = [
      v => !!v || 'Ce champ est requis',
      v => isEmailValid(v) || 'Format d\'email invalide'
    ]
    
    // Règles de validation pour la date de début
    // isDateValidUtil retourne true ou un code d'erreur : comparaison stricte
    const startDateRules = [
      v => !!v || 'Ce champ est requis',
      v => isDateValidUtil(v) === true || 'Format de date invalide (JJ/MM/AAAA)',
      v => !v || !isWeekendDate(v) || 'La date ne peut pas être un week-end'
    ]
    
    // Règles de validation pour la date de fin
    const endDateRules = computed(() => [
      v => !!v || 'Ce champ est requis',
      v => isDateValidUtil(v) === true || 'Format de date invalide (JJ/MM/AAAA)',
      v => !v || !isWeekendDate(v) || 'La date ne peut pas être un week-end',
      v => !v || !formData.startDate || isDateAfter(formData.startDate, v) || 
        'La date de fin doit être postérieure à la date de début'
    ])
    
    // v-form.validate() est asynchrone en Vuetify 3
    const submitForm = async () => {
      const { valid } = await form.value.validate()
      if (valid) {
        // Traitement du formulaire
        console.log('Formulaire valide', formData)
      }
    }
    
    return {
      form,
      isFormValid,
      formData,
      emailRules,
      startDateRules,
      endDateRules,
      submitForm
    }
  }
}
</script>
`}/>

## Bonnes pratiques

- Utilisez `propValidator` pour valider les props de vos composants avec des valeurs spécifiques
- Utilisez `ruleMessage` dans vos fabriques de règles personnalisées pour permettre la surcharge des messages
- Combinez les différentes fonctions de validation pour créer des règles de validation complexes
- Validez toujours les dates avant de les utiliser dans des calculs ou des comparaisons
- Attention aux **formats attendus** : `DD/MM/YYYY` pour `isDateAfter`, `isDateBefore`, `isDateValidUtil` — ISO `YYYY-MM-DD` pour `isDateInRange`, `isWeekend`
- Pour les validations de formulaire, préférez les règles prêtes à l'emploi du Design System (voir [Règles de validation](/?path=/docs/guide-du-dev-utilitaires-r%C3%A8gles-de-validation--docs)) qui gèrent déjà ces subtilités
