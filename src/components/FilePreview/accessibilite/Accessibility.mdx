  <CriteriaSection>

    <CriteriaCard title="Prévisualisation des images">
      <ul>
        <li><strong>Image native</strong> : Utilisation de l'élément HTML <code>&lt;img&gt;</code></li>
        <li><strong>Texte alternatif</strong> : Support de l'attribut <code>alt</code> via <code>options.image.alt</code></li>
        <li><strong>Compatibilité</strong> : Restitution native par les technologies d'assistance</li>
        <li><strong>Conformité</strong> : Respect du critère RGAA 1.1 relatif aux images porteuses d'information</li>
      </ul>
    </CriteriaCard>

    <CriteriaCard title="Prévisualisation des PDF">
      <ul>
        <li><strong>Intégration native</strong> : Utilisation de l'élément <code>&lt;object&gt;</code></li>
        <li><strong>Type explicite</strong> : Déclaration du MIME type <code>application/pdf</code></li>
        <li><strong>Fallback accessible</strong> : Message affiché lorsque la prévisualisation n'est pas disponible</li>
        <li><strong>Compatibilité variable</strong> : Le rendu dépend du navigateur et du lecteur PDF disponible ; sans lecteur intégré, l'aperçu bascule automatiquement sur pdf.js (voir la carte suivante)</li>
      </ul>
    </CriteriaCard>

    <CriteriaCard title="⚠️ Aperçu pdf.js (readonly / suivi de consultation) — non accessible">
      <ul>
        <li><strong>Rendu visuel uniquement</strong> : avec <code>readonly</code> ou <code>track-consultation</code>, le PDF est rendu via <strong>pdf.js</strong> dans des <code>&lt;canvas&gt;</code>, <strong>sans couche de texte</strong> (le conteneur des pages est <code>aria-hidden="true"</code>).</li>
        <li><strong>Non restitué par les lecteurs d'écran</strong> : le contenu du document n'est pas lisible par les technologies d'assistance ; pas de sélection ni de recherche de texte.</li>
        <li><strong>Nom accessible</strong> : le conteneur scrollable porte <code>role="document"</code>, <code>tabindex="0"</code> et le libellé <code>documentLabel</code> (« Aperçu du document » par défaut, surchargeable via la prop <code>locales</code>). Il est donc atteignable au clavier et annoncé, même si son contenu ne l'est pas.</li>
        <li><strong>Alternative obligatoire</strong> : fournir une version accessible du contenu (texte/HTML équivalent, lien de téléchargement du PDF source…). La prévisualisation pdf.js ne doit <strong>jamais</strong> être l'unique moyen d'accès à l'information.</li>
        <li><strong>À réserver</strong> aux besoins spécifiques de ces modes (masquer le téléchargement/l'impression, suivi de lecture obligatoire) ; sinon préférer l'aperçu natif <code>&lt;object&gt;</code>.</li>
        <li><strong>Également utilisé en repli automatique</strong> : sur les navigateurs sans lecteur PDF intégré (Chrome sur Android), l'aperçu bascule seul sur pdf.js. Ces limites s'appliquent alors <strong>sans que la prop ait été activée</strong> : l'alternative accessible au document reste indispensable.</li>
      </ul>
    </CriteriaCard>

    <CriteriaCard title="Gestion des formats non supportés">
      <ul>
        <li><strong>Message alternatif</strong> : Affichage d'un contenu de remplacement lorsque le type de fichier n'est pas prévisualisable</li>
        <li><strong>Slot personnalisé</strong> : Possibilité de fournir un message métier adapté</li>
        <li><strong>Compréhension utilisateur</strong> : Évite les zones vides ou silencieuses</li>
      </ul>
    </CriteriaCard>

    <CriteriaCard title="Informations accessibles">
      <ul>
        <li><strong>Texte alternatif pertinent</strong> : Fournir un <code>alt</code> descriptif lorsque l'image apporte une information</li>
        <li><strong>Image décorative</strong> : Utiliser un <code>alt=""</code> lorsque l'image n'apporte aucune information utile</li>
        <li><strong>Message de secours</strong> : Les utilisateurs sont informés lorsqu'un aperçu ne peut être affiché</li>
        <li><strong>Navigation clavier</strong> : Aucun comportement spécifique requis car le composant n'est pas interactif</li>
      </ul>
    </CriteriaCard>

  <BestPracticesSection>
    <ul>
      <li>Renseigner systématiquement <code>options.image.alt</code> pour les images informatives.</li>
      <li>Prévoir un message explicite pour les formats non pris en charge.</li>
      <li>Ne pas utiliser la prévisualisation comme unique moyen d'accéder au document.</li>
      <li><strong>Modes <code>readonly</code> / <code>track-consultation</code> (pdf.js)</strong> : le rendu <code>&lt;canvas&gt;</code> n'est <strong>pas accessible</strong> aux lecteurs d'écran — fournir impérativement une alternative textuelle et/ou un accès au document source.</li>
      <li>Fournir un lien de téléchargement complémentaire lorsque cela est pertinent.</li>
      <li>Tester les PDF sur plusieurs navigateurs car leur rendu dépend des capacités natives.</li>
      <li>Vérifier que le contraste des contenus affichés respecte les exigences d'accessibilité.</li>
    </ul>
  </BestPracticesSection>
