# DatePicker — changement de contrat

Le contrat de `update:modelValue`, de `date-selected` et du `validate` des règles personnalisées change.

## `update:modelValue`

Émet désormais `null` (payload `string | string[] | null`) dès que la saisie devient invalide ou incomplète :

- format invalide
- date non parsable
- plage incomplète
- saisie partiellement effacée

Auparavant, le modèle conservait la dernière valeur valide pendant une saisie incomplète, ce qui le désynchronisait du texte affiché.

## `date-selected`

N'est émis que lorsqu'une sélection est complète (date unique confirmée ou plage complète) : il n'est plus émis lorsque seule la première borne d'une plage est saisie au clavier.

## Règles personnalisées (`customRules`, `customWarningRules`, `customSuccessRules`)

**Changement potentiellement cassant** pour les projets où `dateFormatReturn` diffère de `format`.

Lorsque `validate` reçoit une chaîne, elle est désormais au format **`dateFormatReturn || format`** (ex. `'2026-10-07'` avec `dateFormatReturn="YYYY-MM-DD"`), comme le `v-model`, et non plus au format d'affichage. Sans `dateFormatReturn`, rien ne change.

Le type reçu dépend du mode du composant (inchangé par cette version) :

| Composant / mode | `validate` reçoit |
|---|---|
| `DatePicker` avec `noCalendar` | une chaîne |
| `DatePicker` en mode calendrier (saisie clavier ou sélection) | un objet `Date` |
| `DatePicker` avec `useCombinedMode` | à la saisie (blur) : une chaîne ; à la soumission (`validateOnSubmit`, `SyForm`) : une chaîne **puis** un objet `Date` |
| Champ vide | `null` |

Attention :

- une règle qui parsait la chaîne au format d'affichage (ex. `parseDate(value, 'DD/MM/YYYY')`) devient fausse sans lever d'erreur ;
- en `useCombinedMode`, une règle écrite uniquement pour une chaîne (ex. `value.includes('2025')`) reçoit un `Date` à la soumission et refuse une date valide (#2681).

Une règle qui parse avec le format de retour fonctionne dans tous les modes, `null` compris. `parseDate` (via `useDateFormat`) accepte aussi bien une chaîne qu'un objet `Date` :

```ts
import { useDateFormat } from '@cnamts/synapse'

const { parseDate } = useDateFormat()

const notIn2025 = {
	type: 'custom',
	options: {
		validate: (value: unknown) => {
			const date = typeof value === 'string' || value instanceof Date
				? parseDate(value, 'YYYY-MM-DD') // dateFormatReturn || format
				: null
			return !date || date.getFullYear() !== 2025
		},
		message: 'Pas de 2025',
	},
}
```

## Conduite à tenir

Si votre projet écoutait `date-selected` pour récupérer la première borne d'une plage, ou s'appuyait sur la persistance du modèle pendant une saisie incomplète, il faut l'adapter : **le modèle vaut désormais `null` tant que la saisie n'est pas complète et valide**.

Si vos règles personnalisées utilisent `dateFormatReturn` différent de `format`, parsez la valeur avec `parseDate(value, dateFormatReturn || format)`, qui couvre tous les modes du tableau ci-dessus, `null` compris.
