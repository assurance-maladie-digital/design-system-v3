# Nouvelle prop `validateOn` sur les champs

Tous les composants de champ de formulaire à l'exeption des dates pickers acceptent une nouvelle prop `validateOn` qui détermine le déclencheur de la validation Vuetify : `blur`, `input`, `submit`, `invalid-input`, combinables avec les modificateurs `lazy` et `eager` (ex. `eager blur`).

Elle ne s'applique qu'en mode Vuetify (`useVuetifyValidation`) et **remplace `isValidateOnBlur`** si les deux sont fournies. En mode Synapse, elle est ignorée et un warning est émis en développement.

Cas particulier de `SyTextArea` : le composant déclarait déjà `validateOn` (avec `eager input` par défaut), mais ne l'appliquait pas. Les valeurs de `validate-on` explicitement définies sont désormais prises en compte ; avec `eager`, les erreurs peuvent s'afficher dès le chargement.

## Conduite à tenir

- Pour choisir quand la validation se déclenche en mode Vuetify, utilisez `validate-on` ; il remplace `is-validate-on-blur` si les deux sont fournis.
- Vérifiez les valeurs de `validate-on` existantes sur `SyTextArea` et adaptez-les si nécessaire, car elles influencent désormais le déclenchement de la validation.
- En mode Synapse, continuez d'utiliser `isValidateOnBlur` : `validateOn` n'y a aucun effet.

# SyTextField — prop `direction` supprimée

La prop `direction` de `SyTextField` n'a jamais eu d'effet : `VTextField` ne la prend pas en charge, et la valeur finissait en attribut HTML invalide `direction="horizontal"` sur l'`<input>` (RGAA 8.2, code source valide). La prop est supprimée : elle n'est plus déclarée dans les props, les types (`SyTextFieldProps`) ni la documentation. Tous les composants construits sur `SyTextField` sont concernés (`PhoneField`, `NirField`, `PasswordField`, `DatePicker`, etc.).

Le rendu ne change pas. Un `direction="…"` encore passé à `SyTextField` est ignoré : il n'est pas transmis à l'`<input>`.

## Conduite à tenir

- Retirez `direction` de vos usages de `SyTextField`. Si vos templates sont vérifiés en mode strict (`strictTemplates`), ou si vous construisez les props en TypeScript à partir de `SyTextFieldProps`, la propriété `direction` y est désormais signalée comme inconnue.
- Si vos tests ou snapshots attendaient l'attribut `direction` sur l'`<input>`, mettez-les à jour.

# Nouveau point d'entrée `@cnamts/synapse/vuetifyOptions` — ajout au contrat

Un nouveau point d'entrée exporte `createVuetifyOptions`. La fonction renvoie la configuration Vuetify de Synapse (thèmes, `defaults`, locale, icônes) sans enregistrer les composants ni les directives Vuetify.

`createVuetifyInstance` (`@cnamts/synapse/vuetifyConfig`) ne change pas : elle est désormais construite sur `createVuetifyOptions` et enregistre toujours tous les composants et directives.

Cet ajout n'est pas cassant.

## Conduite à tenir

C'est désormais la configuration recommandée : `vite-plugin-vuetify` (import automatique des composants) et `createVuetifyOptions`. La documentation ne présente plus qu'elle, dans la section « Configurer Vuetify » de la page *Guide Du Dev / Démarrage / Installation*, qui remplace la page *createVuetifyInstance*.

```ts
import { createVuetify } from 'vuetify'
import { createVuetifyOptions } from '@cnamts/synapse/vuetifyOptions'

export const vuetify = createVuetify(createVuetifyOptions())
```

Les composants Vuetify inutilisés ne sont alors plus inclus dans votre bundle.

`createVuetifyInstance` reste disponible et fonctionne comme avant : vous pouvez la garder.

# PeriodField — règles de validation ciblées par borne

Nouvelles props `customFromRules` / `customToRules`, ainsi que `customFromWarningRules` / `customToWarningRules` : les règles passées dans ces props ne s'appliquent qu'à la date de début ou de fin, ce qui permet d'afficher des messages différents pour chaque borne.

`customRules` et `customWarningRules` restent inchangés : leurs règles continuent de s'appliquer aux deux bornes. L'option `fieldIdentifier` d'une règle sert à rattacher le message au champ visé, elle ne restreint pas la portée de la règle.

## Conduite à tenir

- Si vous utilisiez `fieldIdentifier` dans `customRules` / `customWarningRules` pour cibler une seule borne, la règle s'appliquait en réalité aux deux : déplacez-la vers `customFromRules` / `customToRules` (ou `customFromWarningRules` / `customToWarningRules`) et retirez `fieldIdentifier`.
